# בדיקת חנויות נדרים קארד — שלוחה קולית + אתר ניהול

שלוחה בקו של טכנוליין שבה מתקשר אומר שם של חנות, והמערכת עונה מיד האם היא
נמצאת ברשימת החנויות של נדרים קארד. כל פנייה נרשמת ביומן שאפשר לצפות בו
באתר ניהול: מה נאמר, מאיזה טלפון, ומה הייתה התשובה.

---

## למה יש DB ולא פנייה ישירה לנדרים

`GetStoresList` מחזיר את **כל** רשימת החנויות ותו לא — אין בו חיפוש לפי שם.
כדי להתאים שם שנקלט ב‑STT צריך להשוות אותו מול הרשימה כולה, ולכן הרשימה
נשמרת מקומית ומתרעננת כל 5 שעות. כך גם התשובה בטלפון מיידית (מילישניות
במקום קריאת רשת), וגם נשמרת היסטוריה של שינויים ברשימה.

## מבנה

```
PBX טכנוליין ──GET──▶ /ivr   ──▶ SQLite ◀──  משיכה כל 5 שעות ──▶ נדרים פלוס
                                    │                              GetStoresList
דפדפן  ──────────────▶ /  , /api ───┘                              GetLimitedStoresList
```

| רכיב | קובץ | תפקיד |
|---|---|---|
| שלוחה קולית | `src/ivr.js` | מחזיר מודולי JSON ל‑PBX לפי מצב השיחה |
| מנוע התאמה | `src/matcher.js` | נרמול עברית, שלד עיצורים, פונטיקה, התאמת מילים |
| סנכרון | `src/nedarim.js` | משיכת חנויות וקבוצות מנדרים, יומן ריצות |
| מסד נתונים | `src/db.js` | SQLite: חנויות, כינויים, יומן פניות, הגדרות |
| אתר ניהול | `src/admin.js`, `src/public/` | יומן, חיפוש, כינויים, ארגז חול, הגדרות |

## פריסה בקפרובר

1. **צרו אפליקציה** בשם `store-checker`, עם `Has Persistent Data` מסומן.
2. **נפח קבוע** בלשונית App Configs → Persistent Directories:
   `Path in App: /app/data`, ותנו לו label כלשהו.
   בלי זה המאגר נמחק בכל דיפלוי.
3. **משתני סביבה** (App Configs → Environmental Variables):

   | משתנה | ערך |
   |---|---|
   | `NEDARIM_MOSAD_ID` | מספר המוסד, 7 ספרות |
   | `NEDARIM_API_PASSWORD` | מפתח שנוצר בנדרים: הגדרות ← API ← מפתחות API (מתחיל ב‑`npk_`) |
   | `ADMIN_USER` | שם משתמש לאתר הניהול |
   | `ADMIN_PASSWORD` | סיסמה חזקה |
   | `SESSION_SECRET` | `openssl rand -hex 32` |
   | `IVR_TOKEN` | מחרוזת אקראית — מגינה על כתובת השלוחה |
   | `SYNC_INTERVAL_HOURS` | `5` |

   שאר המשתנים ב‑`.env.example` הם אופציונליים.
4. **Container HTTP Port**: `80`.
5. **דיפלוי**: `caprover deploy` מהתיקייה, או חיבור ל‑Git (לשונית Deployment →
   Deploy from Github/Bitbucket/Gitlab). בשדה Branch כתבו `main` באותיות קטנות —
   גיט מבדיל בין אותיות גדולות וקטנות, ו‑`MAIN` נכשל בשיבוט. קפרובר מזהה את
   `captain-definition` לבד.
6. **HTTPS**: הפעילו Force HTTPS. חובה — הסיסמאות והעוגייה עוברות שם.
7. היכנסו לאתר, לשונית "סנכרון והגדרות", ולחצו **סנכרון עכשיו**. אמורות
   להופיע החנויות.

> **חשוב:** למפתח ה‑API בנדרים צריכות להיות הרשאות ל‑`GetStoresList`.
> אם הפעולה לא כלולה בהרשאות המפתח היא תידחה גם שהיא מתועדת.

## חיבור השלוחה בטכנוליין

צרו שלוחה מסוג API והזינו בה את הכתובת:

```
https://store-checker.YOUR-DOMAIN/ivr?token=<IVR_TOKEN>
```

זה כל מה שצריך. ה‑PBX פונה לכתובת הזו ב‑GET בכל שלב של השיחה, והשרת מחזיר
את המודול הבא. לפי התיעוד אין ב‑Module API מפתח אימות — הכתובת עצמה היא
המזהה, ולכן ה‑`token` מוסיף שכבת הגנה על כתובת שדלפה.

### זרימת השיחה

```
שיחה נכנסת
   └─ stt "אמרו את שם החנות"           → say1
      ├─ התאמה חד-משמעית  → "החנות X נמצאת ברשימת החנויות המאושרות"
      ├─ התאמה בינונית    → "האם התכוונתם ל…?" (עד 3 אפשרויות, 9 = לא) → conf1
      └─ אין התאמה        → "לא נמצאה חנות בשם…"
   └─ "לחנות נוספת הקישו 1, לסיום 2"    → more1
      └─ 1 → חוזר ל-stt עם say2 … עד MAX_ATTEMPTS
```

השרת חסר מצב לחלוטין: ה‑PBX צובר את כל הערכים בכתובת (`say1`, `conf1`,
`more1`, `say2`…), והשרת מחליט מה להחזיר לפי מה שקיים. לכל ניסיון `name`
נפרד, כדי שערכים לא ידרסו זה את זה.

התשובה מבחינה בין שני מצבים לפי השדה `Enabled` שמגיע מנדרים:
"נמצאת ברשימת החנויות המאושרות" מול "קיימת במערכת, אך ההסכם מולה אינו פעיל".

## איך עובד הזיהוי

STT טלפוני לא מחזיר את השם המדויק. המנוע משווה בארבע רמות ולוקח את הציון
הגבוה מביניהן:

1. **טקסט מנורמל** — הסרת ניקוד, גרשיים, פיסוק, ואותיות סופיות.
2. **שלד עיצורים** — בלי א‌ה‌ו‌י‌ע. תופס "לוי" מול "לווי", כתיב מלא מול חסר.
3. **מפתח פונטי** — ט↔ת, ח↔כ↔ק, ב↔ו, ש↔ס. תופס שגיאות תעתיק של המנוע.
4. **התאמת מילים** — לכל מילה בשאילתה מחפשים מקבילה בשם החנות.

בנוסף:
- משפטים שלמים מקולפים: "אני רוצה לבדוק את אושר עד בבקשה" → "אושר עד".
- פתיחת שם של רשת מקבלת חיזוק, כך ש"רמי לוי" עונה מיד על "רמי לוי שיווק השקמה".
- שם מדויק מנצח סניפים קרובים: "אקסוס" מכריז מיד ולא שואל "אקסוס או אקסוס צפת?".
- שם דו-לשוני נבדק גם לפי החלק העברי בלבד: "ריל מן" מתאים ל‑"REAL MAN - ריל מן".
- כפילויות ברשימה של נדרים (רשומה ישנה מושבתת לצד רשומה פעילה באותו שם)
  מוצגות פעם אחת, עם עדיפות לרשומה הפעילה.
- שמות באנגלית בלבד (CHEMISE, LICHI) לא ניתנים להתאמה מדיבור עברי — לכל אחד
  כזה מוסיפים כינוי עברי בלשונית "כינויים", עדיף מראש ולא אחרי שיחה שנכשלה.

**הכיוונון האמיתי הוא הכינויים.** כשמתקשר אומר שם שהמערכת לא מזהה, הפנייה
מופיעה באתר עם כפתור "שייך לחנות". לחיצה יוצרת כינוי קבוע, ובפעם הבאה
הזיהוי מיידי. עדיף להשתמש בזה מאשר להוריד את הספים — הורדת סף מייצרת
זיהויים שגויים בכל הקו, כינוי מתקן מקרה אחד.

הספים ניתנים לשינוי דרך `AUTO_THRESHOLD` (ברירת מחדל 0.90 — מכריז מיד)
ו‑`CONFIRM_THRESHOLD` (0.62 — שואל לאישור). לפני שמשנים, כדאי לבדוק
בארגז החול שבלשונית "חנויות": מקלידים שם ורואים בדיוק מה הקו יענה.

## אתר הניהול

| לשונית | מה יש בה |
|---|---|
| **פניות** | כל הפניות: מה נאמר, טלפון, שעה, תוצאה. סינון לפי תקופה וסטטוס, חיפוש חופשי, ייצוא לאקסל. שיוך חנות לפנייה שלא זוהתה. |
| **חנויות** | ארגז חול לבדיקת שם, וחיפוש במאגר החנויות המסונכרן. |
| **כינויים** | כל הכינויים שנוצרו, עם אפשרות מחיקה. |
| **סנכרון והגדרות** | מצב הסנכרון האחרון, סנכרון ידני, ובחירה מול איזו קבוצת חנויות לבדוק. |

**קבוצות חנויות** — אם בנדרים מוגדרת קבוצה שמגבילה את הכרטיסים שלכם לחנויות
מסוימות, אפשר לבחור אותה בהגדרות, והקו יבדוק רק מולה. ברירת המחדל היא כל
החנויות שבהסכם.

## תחזוקה

- `GET /healthz` מחזיר מצב ומספר חנויות — שימושי לניטור חיצוני.
- יומן הסנכרונים נשמר בטבלה `sync_runs`, כולל שגיאות. אם סנכרון נכשל,
  המאגר הקודם נשאר בתוקף והקו ממשיך לעבוד.
- גיבוי: העתקת `/app/data/stores.db` (יחד עם קבצי ה‑WAL) מספיקה.
- חנות שירדה מהרשימה בנדרים לא נמחקת אלא מסומנת `in_list=0` — כדי שאפשר
  יהיה להבין בדיעבד למה פנייה ישנה ענתה מה שענתה.
